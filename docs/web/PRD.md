# IPTV-API Web 管理端 产品需求文档（PRD）

版本：v1.0
日期：2026-09-29
适用版本：IPTV-API 3.x

## 1. 项目背景与目标

### 1.1 背景
IPTV-API 当前提供两类本地客户端（tkinter 旧版、PySide6 桌面版），管理操作必须在运行机器本地进行。Docker 用户和远程部署用户缺少便捷的可视化管理手段，只能通过修改挂载卷中的配置文件实现管理。

### 1.2 目标
在不影响现有订阅结果服务的前提下，提供一套基于浏览器的 Web 管理端，使桌面版（PySide6）的核心管理能力可通过浏览器完成，支持远程管理 Docker / 自建部署。

### 1.3 非目标
- 不替换、不改变现有订阅结果接口（m3u / txt / epg / hls_proxy 等）的行为；
- 不做多用户、权限分级、操作审计等企业级能力；
- 不实现桌面端的本地文件对话框级别的能力（本地文件通过浏览器上传/下载替代）；
- 不实现桌面端"在线下载并安装新版本安装包"的能力（容器环境通过重新拉取镜像升级）。

## 2. 用户与使用场景

### 2.1 目标用户
- 在服务器 / NAS 上以 Docker 方式部署 IPTV-API 的用户；
- 自建 Python 环境部署、希望远程管理的用户；
- 上述用户均为单实例管理员。

### 2.2 核心使用场景
1. 浏览器打开管理地址，输入密码登录；
2. 在仪表盘查看运行状态、频道数、有效结果数，手动触发一次更新，并实时查看进度；
3. 在频道中心按分类浏览频道，查看每个频道的测速结果，执行重测、截图、加入白名单、删除、调整输出选择；
4. 在订阅源页面编辑模板、本地源、订阅地址、EPG、白名单、黑名单、别名等文件；
5. 在播放转推页面查看 RTMP 服务状态、选择频道发起转推、停止转推、查看码流监控；
6. 在日志页面查看运行日志、结果日志、测速日志、统计日志、未匹配日志；
7. 在任务历史页面查看历次更新运行记录和操作记录；
8. 在设置页面查看和修改全部配置项；
9. 在关于页面查看版本信息。

## 3. 功能需求

功能完整对齐桌面版 8 个页面。功能编号规则：`M<模块>-<序号>`。

### 3.1 登录认证（M0）
| 编号 | 功能 | 说明 |
|---|---|---|
| M0-1 | 密码登录 | 单密码登录，密码通过配置项提供；未配置密码时使用首次启动默认值并提示修改 |
| M0-2 | 会话保持 | 登录后颁发签名会话，有效期可配置（默认 7 天），过期需重新登录 |
| M0-3 | 退出登录 | 清除会话 |
| M0-4 | 接口鉴权 | 所有 `/api/admin/*` 接口必须登录后可访问，未登录返回 401 |
| M0-5 | 登录保护 | 连续登录失败次数限制（默认 5 次/分钟，基于 IP），防止暴力破解 |

### 3.2 仪表盘（M1）
| 编号 | 功能 | 说明 |
|---|---|---|
| M1-1 | 状态指标卡 | 展示运行状态（空闲/运行中/暂停/取消中）、频道总数、有效结果数、服务状态 |
| M1-2 | 更新控制 | 手动执行一次更新；运行中可暂停、继续、取消 |
| M1-3 | 实时进度 | 展示当前更新步骤标题和进度百分比，数据通过推送实时更新 |
| M1-4 | 频道结果表 | 展示频道名称、健康状态、接口总数、有效数、最佳速度、更新时间，支持搜索 |
| M1-5 | 快捷跳转 | 指标卡点击跳转到对应页面（任务历史/频道中心/转推） |
| M1-6 | 结果入口 | 提供"浏览结果"菜单，跳转现有的订阅结果页（首页 / content / ipv4 / ipv6 / m3u） |
| M1-7 | 下次更新时间 | 展示调度器计算的下次更新时间 |

### 3.3 频道中心（M2）
| 编号 | 功能 | 说明 |
|---|---|---|
| M2-1 | 分类侧栏 | 按分类聚合展示频道数量及健康度分布（健康/告警/离线），支持点击筛选 |
| M2-2 | 频道列表 | 表格展示频道，支持分类视图/列表视图切换、健康度筛选、搜索、刷新 |
| M2-3 | 频道字段 | 复选框、名称（含台标）、分类、健康状态、接口总数、待测数、有效数、已选数、最佳速度、最低延迟、最高分辨率、更新时间 |
| M2-4 | 结果抽屉 | 选中频道后展示该频道全部接口结果，支持筛选（全部/有效/无效/待测）与搜索 |
| M2-5 | 结果字段 | 接口 URL、来源、IP 类型、归属地、运营商、速度、延迟、分辨率、帧率、编码、测试状态、选中排名、测试时间 |
| M2-6 | 新增频道 | 手动新增频道（分类 + 名称） |
| M2-7 | 新增接口 | 向指定频道手动添加接口 URL |
| M2-8 | 删除频道 | 支持单个/批量删除频道及其结果 |
| M2-9 | 删除接口 | 删除指定频道下的接口，支持批量 |
| M2-10 | 重测频道 | 对整个频道的接口重新测速 |
| M2-11 | 重测接口 | 对单个/多个接口重新测速，展示进度 |
| M2-12 | 截图 | 对单个/多个接口截取视频画面，展示截图缩略图、分辨率、状态 |
| M2-13 | 台标管理 | 查看/设置频道台标 |
| M2-14 | 输出选择 | 手动勾选参与输出的接口、调整顺序；支持重置为自动选择 |
| M2-15 | 白名单操作 | 将接口加入白名单 / 黑名单 |
| M2-16 | 播放 | 调用播放器/网页播放接口（Web 端使用浏览器播放或复制 URL） |
| M2-17 | 导入频道 | 上传本地源文件（txt/m3u）解析导入频道 |
| M2-18 | 导出 | 导出频道数据 / 订阅结果为文件下载 |
| M2-19 | 转推联动 | 对选中频道发起/停止 RTMP 转推 |

### 3.4 订阅源（M3）
通过 7 个 Tab 管理以下文件，每个 Tab 均支持"可视化表格编辑 + 原始文本编辑"两种模式：
| 编号 | 数据源 | 对应文件 |
|---|---|---|
| M3-1 | 模板 | config 项 `source_file`（默认 config/demo.txt） |
| M3-2 | 本地源 | config/local.txt |
| M3-3 | 订阅地址 | config/subscribe.txt |
| M3-4 | EPG 源 | config/epg.txt |
| M3-5 | 白名单 | config/whitelist.txt |
| M3-6 | 黑名单 | config/blacklist.txt |
| M3-7 | 别名 | config/alias.txt |

| 编号 | 功能 | 说明 |
|---|---|---|
| M3-8 | 读取解析 | 读取文件并按行解析为结构化行，保留注释 |
| M3-9 | 表格编辑 | 新增、删除、勾选、字段内编辑；模板支持移动到分类；白名单规则列提供下拉 |
| M3-10 | 分类管理（仅模板） | 分类侧栏，新增/重命名/移动/删除分类，查看分类下条目 |
| M3-11 | 原始编辑 | 切换到纯文本编辑模式直接编辑文件内容 |
| M3-12 | 保存 | 校验后写回文件，失败展示错误 |
| M3-13 | 重新加载 | 放弃修改重新读取 |
| M3-14 | 导入文件 | 上传文件替换/合并当前内容 |
| M3-15 | 导出文件 | 将当前内容下载为文件 |
| M3-16 | 搜索 | 按条目内容搜索过滤 |

### 3.5 播放转推（M4）

| M4-2 | 频道选择 | 弹窗列出可转推频道，支持搜索、全选、勾选，受并发上限约束并给出提示 |
| M4-3 | 发起转推 | 对选中频道发起转推；支持直接播放当前选中接口 |

## 4. 实时性需求
- 更新进度、日志、RTMP 带宽、转推列表需要近实时展示；
- 采用**短轮询**方案（与桌面端定时刷新节奏一致）：更新进度约 1s、日志约 1.5s、RTMP 约 2s、任务历史约 3s 轮询对应状态接口；
- 更新/重测等任务在后端后台线程执行，轮询只读取任务管理器维护的状态快照，不阻塞任务本身；
- 页面不可见时暂停轮询，恢复可见时立即拉取一次，减少无效请求。

## 5. 非功能需求
| 类别 | 要求 |
|---|---|
| 兼容性 | 支持 Chrome / Edge / Safari / Firefox 最近 2 个大版本；桌面与平板浏览器自适应，不专门适配手机 |
| 国际化 | 复用现有 i18n 资源，默认跟随 `language` 配置，支持中/英文切换 |
| 性能 | 频道/日志列表分页或虚拟滚动；常规页面首屏加载 < 2s（局域网） |
| 安全 | 密码不明文存前端；会话用服务端密钥签名；管理接口与订阅接口隔离；防暴力破解 |
| 部署 | 前端构建产物随 Docker 镜像打包；不引入必须全局安装的工具；Node 环境安装于项目目录 |
| 可维护 | 后端复用现有业务逻辑模块，不重复实现；前端按页面模块化组织 |

## 6. 约束与依赖
- 后端运行于现有 Flask + gunicorn 服务（单 worker）；
- 业务能力依赖现有模块：`UpdateSource`、`channel_repository`、`channel_operations`、`config`、`user_actions`、`rtmp_stats` 等；
- 前端技术栈：React + Ant Design + Vite，依赖安装于项目目录；
- Web 管理端入口使用独立路径前缀，避免与订阅路由冲突。

## 7. 验收标准
1. 8 个页面全部可访问，未登录访问管理页面跳转登录页；
2. 仪表盘触发更新，进度实时更新，可暂停/取消，与桌面端行为一致；
3. 频道中心增删改查、重测、截图、输出选择功能可用；
4. 订阅源 7 个文件可可视化编辑、原始编辑、保存、导入导出；
5. RTMP 转推全流程（选择、发起、监控、停止）可用；
6. 5 类日志可实时查看、搜索、清空、导出；
7. 任务历史正确合并展示运行与操作记录；
8. 设置项可查看、编辑、保存，重启后生效；
9. 现有订阅结果接口行为完全不受影响；
10. Docker 镜像构建成功并可在浏览器完成上述全部操作。

## 8. 未来扩展（不在本期）
- 多用户与角色权限；
- Web 端在线升级（容器场景）；
- 移动端专门适配；
- 操作审计与告警通知。
